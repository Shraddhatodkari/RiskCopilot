--- Interpretation ---
All measured operations complete in low-single-digit milliseconds or
less on this sandbox machine. Even a laptop 10-20x slower on raw CPU
would keep every one of these steps well under 100ms — none of them
involve a loop over a large dataset or an expensive algorithm; the
actual end-to-end latency of a real run is dominated by network round
trips to data.sec.gov/api.stlouisfed.org (not measurable from this
sandbox) and, when used, the LLM API call (also not measured here —
no live LLM call has been made anywhere in this project). This is the
honest scope of what local compute-bound benchmarking can tell us for
a tool whose real bottleneck is expected to be network I/O, not CPU.
